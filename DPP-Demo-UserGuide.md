# DPP Platform Demo — User Guide
**Sopra Steria · Consulting-Grade Demo · June 2026**

---

## What is this demo?

This is a browser-based, self-contained demonstration of an AI-powered Digital Product Passport (DPP) platform. It simulates what a production DPP system built on a Data Hub would look like for an industrial client — specifically in the battery sector, ahead of the EU Battery Regulation deadline of 18 February 2027.

The demo runs entirely in a single HTML file. Open it in any modern browser (Chrome, Edge, Firefox, Safari). No internet connection, login, or installation is required.

---

## How to open it

1. Locate the file `dpp-demo.html` on your computer.
2. Double-click it — it will open in your default browser.
3. If nothing happens, right-click the file and choose "Open with" → your preferred browser.

---

## The demo at a glance

The platform has five main sections, accessible from the top navigation bar:

| Section | What it shows |
|---|---|
| **Portfolio** | All battery products with their compliance readiness scores |
| **Compliance Cockpit** | Detailed gap analysis for a specific product |
| **Regulatory Radar** | EU regulatory timeline from 2023 to 2030 |
| **Agent Dashboard** | Four AI agents that automate compliance tasks |
| **Interoperability** | Export formats and BaSyx AAS integration |

A floating **DPP Assistant** chat panel is always accessible via the robot icon in the bottom-right corner.

## The Persona Switcher

In the top-right corner, there is a dropdown labelled **"View as"**. This changes the context banner at the top of the Portfolio page to reflect what that type of user cares about most.

| Persona | Represents |
|---|---|
| OEM Client | A large manufacturer reviewing supplier battery compliance |

During a client demo, switch the persona to match who you are presenting to. The platform layout and data do not change — only the contextual framing does.

## Section-by-section walkthrough

### 1. Portfolio Page

This is the home screen. It shows:

- Four key metrics at the top: total battery products, compliant count, gap count, and days remaining to the February 2027 deadline.
- A table of six battery products with their readiness score shown as a progress bar.

**What to do:** Click any row in the table to open the full Digital Product Passport for that battery. The NMC811 has the richest data and is the best starting point for a demo.

The readiness percentage indicates how many of the mandatory attributes under EU 2023/1542 are currently populated and validated.

---

### 2. Product Detail Page (NMC811)

This is the core DPP view. It opens when you click a battery in the Portfolio.

At the top, you will see:
- An **AI-generated executive summary** explaining the product's compliance position in plain language.
- A **compliance ring chart** showing the overall readiness score.
- A **category readiness list** showing all seven regulatory categories at a glance.

Below that are seven **accordion sections**, one per regulatory category. Click any category header to expand it and see:
- Each individual attribute name and its current value.
- A short description of what the attribute measures.
- The regulatory reference (article number and regulation).
- An **AI Regulatory Insight** — a plain-language explanation of why this attribute is required, whether the current value meets expectations, and what to watch for.

**Tip for demos:** Expand the "Battery Carbon Footprint" category first — it has the most complete data and the clearest AI explanations. Then navigate to "Supply Chain Due Diligence" to show the sourcing declarations.

The left sidebar lets you jump directly to any category without scrolling.

---

### 3. Compliance Cockpit

This page shows a compliance gap analysis.

At the top, two panels appear side by side:
- **Fleet Readiness** — a ring chart showing 84% overall readiness across all 11 products, broken down by compliant, partial, and gap categories.
- **AI Priority Actions** — three colour-coded alerts generated by the AI, showing which products need immediate attention, which have minor issues, and which are fully ready.

Below that is the **Attribute Gap Register** for the NMC955-G battery. This is a table showing every relevant attribute, its coverage status, the regulatory article it comes from, the deadline, and a priority rating.

At the bottom, the **Generate Audit Package** button simulates what the Audit Preparation Agent would produce — a regulation-cited PDF document ready for a market surveillance authority.

---

### 4. Regulatory Radar

This page shows the full EU regulatory timeline from 2023 to 2030.

Each entry on the timeline represents a regulatory milestone:
- A green dot means the requirement is already met.
- A gold pulsing dot marks the current position (June 2026 — active preparation window).
- Grey dots are upcoming requirements.

Each milestone card explains what the requirement is, which article it comes from, and how your current portfolio maps to it.

Below the timeline, a second table shows upcoming ESPR delegated acts for other product categories (steel, textiles, tyres, furniture) — useful for showing the client that this platform scales beyond batteries.

---

### 5. Agent Dashboard

This page demonstrates the four AI agents that automate compliance work. This is one of the strongest differentiators in the demo.

Each agent card shows:
- What the agent does.
- Its current status (Running, Awaiting Response, or Idle).
- A live log of its last actions.
- Action buttons to trigger a run or approve a proposal.

**Agent 1 — Regulatory Monitor:** Scans the EU Official Journal and ESPR pipeline for new delegated acts. When it finds a change, it proposes new attributes. In the demo, it has already detected a draft Steel DPP act and drafted 14 new attribute proposals. Click "Review Proposals" to simulate approval.

**Agent 2 — Data Completeness Enforcer:** Monitors all products for missing attribute values. It has detected 3 missing Supply Chain attributes on LCO-G and sent supplier requests. One supplier is now 12 days overdue. Click "Approve Escalation" to simulate escalation.

**Agent 3 — Attribute Lifecycle Manager:** Takes a regulatory document as input and drafts new attribute definitions. It ran on a textiles delegated act and produced 23 new attributes, which were approved. Click "Upload & Analyse" to simulate a new run.

**Agent 4 — Audit Preparation Agent:** Assembles a complete, regulation-cited audit package on demand. Select a battery from the dropdown and click "Generate Package" to see the simulated log.

**Important governance note:** All agents propose — none auto-publish. Every action requires human approval. This is explained in the blue notice at the top of the page and is a deliberate design decision for enterprise trust.

**How to run an agent live in a demo:** Click "Run Now" or "Upload & Analyse" on any agent card. The log will update in real time, line by line, simulating the agent working. This takes about 3–4 seconds.

---

### 6. Interoperability Page

This page shows how the DPP connects to external systems.

The left panel shows the three-layer architecture:
- Data Hub at the top (system of record — nothing changes here).
- DPP API Gateway in the middle (transformation layer).
- BaSyx AAS Registry at the bottom (system of exchange — the international standard for digital twins and product data).

The right panel shows the BaSyx registry connection status with 11 registered submodels.

Below, six export format cards allow you to simulate exporting a product's DPP in different formats. Click any card to see a toast confirmation. Available formats: AAS Submodel JSON, AASX Package, JSON-LD, REST API, QR Code, Audit PDF.

---

### DPP Assistant (AI Chatbot)

The robot icon in the bottom-right corner opens the DPP Assistant chat panel. It is available on every page.

It is pre-loaded with four suggested questions — click any of them to trigger a response without typing. The responses are pre-scripted to represent what an AI with full regulatory knowledge and product context would say.

**Suggested demo flow:**
1. Click "Is NMC811 ready for 2027?" — shows a structured compliance answer.
2. Click "What is missing on LCO-G?" — shows a gap analysis with specific article references.
3. Click "What is required in 2028?" — shows forward regulatory planning.
4. Click "Explain Art. 7 carbon footprint" — shows regulatory interpretation capability.

You can also type any question. If the text matches one of the four pre-loaded responses, it will reply correctly. Otherwise it returns a generic fallback.

## Recommended demo narrative (15 minutes)

| Time | Action |
|---|---|
| 0–2 min | Open Portfolio. Explain what a DPP is and why it is mandatory. Switch persona to match the audience. |
| 2–5 min | Click NMC811. Walk through the executive summary and compliance ring. Open two or three category accordions. Show the AI Regulatory Insights. |
| 5–8 min | Navigate to Compliance Cockpit. Show the gap analysis table. Point out the AI priority actions. Click Generate Audit Package. |
| 8–10 min | Navigate to Regulatory Radar. Walk the timeline from today to 2027 and 2028. |
| 10–13 min | Navigate to Agent Dashboard. Run Agent 1 and Agent 4 live. Approve Agent 2 escalation. Emphasise human-in-the-loop governance. |
| 13–15 min | Open the DPP Assistant. Ask two questions. Close with the Interoperability page to show standards alignment. |

## What is real vs. simulated in this demo

| Feature | Status |
|---|---|
| DPP data structure and attribute categories | Real — mirrors EU 2023/1542 Annex XIII |
| Regulatory references (article numbers) | Real — verified against the regulation |
| Compliance readiness scores | Simulated — fixed values for demo purposes |
| AI regulatory insight texts | Pre-scripted — represent what an LLM would produce |
| DPP Assistant chat responses | Pre-scripted — four fixed Q&A pairs |
| Agent log animations | Simulated — step-by-step log display with timed delays |
| BaSyx registry connection | Simulated — status shown as connected, no live call |
| Export downloads | Simulated — toast notification only, no file generated |

In a production implementation, all simulated elements would be backed by live data from the Data Hub, real Claude API calls, and a live BaSyx registry.

## Customising the demo for a specific client

Before presenting to a client:

1. Update the persona dropdown label ("OEM Client") to the client's industry if appropriate — e.g., "Automotive OEM" or "Industrial Manufacturer".
2. Replace the demo product names (NMC811, LCO-G, etc.) with product names relevant to the client's sector if they are not in batteries.
3. Adjust the "Days to Feb 2027" counter if needed — it is currently hardcoded to 606.
4. In the chatbot, the four pre-scripted answers can be updated to reference the client's actual products or context.

All of this requires editing the HTML file in a text editor. The relevant sections are clearly labelled in the JavaScript at the bottom of the file.
